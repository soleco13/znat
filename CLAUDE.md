# Контекст проекта

Видеоплатформа для одной онлайн-школы. Монолит на одном сервере.
Спецификация: ./docs/ТЗ.md — читай перед архитектурными решениями.
План: ./docs/ПЛАН.md — текущий этап указан в ./docs/CURRENT_STAGE.md

# Стек (не менять без обсуждения)

Node 22 + Fastify + TypeScript + Drizzle + PostgreSQL 17 + Redis 7
React 19 + Vite + Tailwind + Zustand
LiveKit (self-hosted), Yjs + Hocuspocus, Excalidraw

# Железные правила

- НЕ добавлять зависимости без явного разрешения. Предложить и дождаться ответа.
- НЕ использовать localStorage/sessionStorage.
- Модуль экспортирует только service.ts. Никто не импортирует чужой repo.ts.
- Модуль не импортирует таблицы чужого модуля напрямую — только через его сервис.
- Никаких циклических зависимостей между модулями (проверяется `dependency-cruiser` в CI).
- Все внешние адреса — через env. Ни одного захардкоженного localhost.
- Доступ к файлам — только через StorageAdapter. Ни одного `fs.readFile` в бизнес-логике.
- Схемы Zod живут в packages/shared и используются и фронтом, и бэком, без логики.
- Ничего с чужих CDN. Шрифты, KaTeX, иконки — в бандле.
- Ключи ответов на задания никогда не уходят на клиент до сабмита.
- Никакого состояния в памяти процесса, кроме кешей, которые можно потерять.

# Правило допуска внешних сервисов (§1.2, §10.10 ТЗ)

Перед добавлением любого внешнего сервиса — три вопроса:
1. Он платный (сейчас или станет платным)? → ДА → отказ
2. Урок остановится или деградирует, если он ляжет? → ДА → отказ
3. Уход от него потребует переделки архитектуры? → ДА → отказ
Все три «нет» → можно. Build-time и observability — внешнее бесплатное ок (GitHub, npm, UptimeRobot). Runtime критического пути урока — только своё.

# Как работать

- Один этап = один контекст. Не смешивать этапы в одной сессии.
- Сначала Zod-схема и типы, потом реализация.
- Каждая задача заканчивается зелёными тестами и рабочим `docker compose up`.
- Если задача выходит за рамки текущего этапа — остановись и скажи об этом.
- Definition of Done: `pnpm build` без ошибок и без `any`; `pnpm test` зелёный; `docker compose up` поднимается с нуля; фича проверена руками; нет новых зависимостей кроме согласованных; `dependency-cruiser` не ругается.

# Что не делегировать вслепую (даже себе — читать построчно)
