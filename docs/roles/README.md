# Ролевая модель, пространства и доступ — план внедрения

Спецификация владельца от 25.10.2026 — [spec-2026-10-25.md](spec-2026-10-25.md) (текст без изменений).
Ниже — что из неё уже есть в коде, чего нет, и этапы внедрения.

## Что есть сейчас (на 25.10.2026)

| Требование | Сейчас | Разрыв |
|---|---|---|
| Единый аккаунт, членство в нескольких пространствах (§7) | `users.school_id` + одна `users.role`; почта уникальна глобально | Нет членства: одна почта — один аккаунт в одной школе. Репетитор не может вступить в школу без второго аккаунта |
| Совмещение учитель + методист (§4.4) | Одна роль на пользователя | Нужны роли набором в членстве |
| Супер-админ глобально (§2) | `SUPER_ADMIN_EMAILS`, раздел «Платформа»: школы, пользователи, платежи, подписки, ручной тариф | Нет просмотра аудиторий, записей и материалов пространств, входа в аудитории, блокировки пространств и аккаунтов |
| Общая библиотека «Матиса» (§2.3, §6.1) | Материалы служебной школы `kind = 'platform'` видны другим | Спецификация: не хранить как материалы отдельной школы; доступ по тарифу; управление — супер-админ |
| Материалы принадлежат пространству (§6.3) | `materials.school_id` есть; `created_by` → users **ON DELETE restrict** | Удаление аккаунта автора упирается в материалы — нужно `set null` и авторство как информационное поле |
| Методист без записей уроков (§4.3) | `GET /recordings…` разрешён `admin, methodist, teacher` | Убрать методиста из записей |
| Учитель — только назначенные аудитории (§4.2) | Учитель видит свои уроки (`teacher_id`) | В основном совпадает, проверить комнату и записи |
| Индивидуальный репетитор (§5) | Личное пространство `kind = 'individual'`; регистрация даёт роль **admin**; тариф и оплата — есть | Роль при регистрации; нет своей библиотеки; доступ к общей — по тарифу |
| Приглашения (§8) | Ссылка-приглашение с ролью; принятие = **регистрация нового аккаунта** | Нет принятия существующим аккаунтом, приглашения на почту, повторной отправки, прекращения членства |
| Тарифы школы и репетитора независимы (§9) | `schools.billing_plan / paid_until`, платежи и подписки на пространство | Совпадает; лимиты тарифа ещё не применяются |
| Проверки на сервере (§10) | Да, `requireRole` + `schoolId` из токена | Переход на роли-наборы из членства |

## Этапы

Каждый этап — отдельный контекст (CLAUDE.md), с миграцией, тестами и проверкой на стенде.

1. **Э15.1 Членство** — сделано 25.10.2026: `memberships` (миграция 0038 переносит всех), токен на выбранное пространство с `roles`, `/auth/spaces`, `/auth/switch`, сессия помнит пространство (`refresh_tokens.school_id`), прекращение членства закрывает доступ без отката в «домашнюю» школу, переключатель в шапке и меню учителя. Принятие приглашения существующим аккаунтом — Э15.2.
   Было в плане: Таблица `memberships (user_id, school_id, roles[], status)`; перенос всех нынешних пользователей в членство со своей ролью; токен выдаётся на выбранное пространство с набором ролей; `requireRole` проверяет пересечение набора; переключатель пространств в шапке; вход открывает последнее пространство. `users.school_id/role` остаются на время перехода, потом удаляются.
2. **Э15.2 Приглашения** — сделано 25.10.2026: принять приглашение вошедшим аккаунтом (`POST /invites/accept`, роль добавляется к членству), приглашение на почту (одноразовое, 14 дней, только этот адрес, фирменное письмо), «Отправить ещё раз» с новой ссылкой, страница «Участники» (роли набором, «Исключить» и «Вернуть»). Ограничение методистов по тарифу — в Э15.6.
   Было в плане: Принятие приглашения существующим аккаунтом (вход → «Вступить»); приглашение на почту (фирменное письмо); статусы, отзыв, повторная отправка; прекращение членства админом (аккаунт, личные данные и материалы школы сохраняются); методист в приглашении — по тарифу школы.
3. **Э15.3 Права по ролям** — сделано 25.10.2026: методист без записей уроков; материалы правит админ или методист, в т. ч. учитель-методист (сервер и интерфейс); автор материала, версий и картинок — справочное поле (`set null`, миграция 0040); репетитор — учитель личного пространства (регистрация и миграция 0041), после подтверждения почты получает «Мою аудиторию» до лимитов тарифа (Э15.6).
   Было в плане: Методист без записей; методист работает со всеми материалами школы; учитель без редактирования материалов, если не методист; материалы переживают автора (`created_by` → nullable, `set null`); регистрация репетитора — роль учителя в личном пространстве; у репетитора нет своей библиотеки.
4. **Э15.4 Супер-админ** — сделано 25.10.2026: супер-админ определяется по почте (`SUPER_ADMIN_EMAILS`), «Открыть пространство» в карточке «Платформы» входит в любое пространство администратором (аудитории, уроки, записи, материалы); блокировка пространства (`schools.blocked_at`, миграция 0042) и аккаунта (`users.is_active`) — на сервере: при входе, в каждом запросе (кеш 30 с) и для гостей по ссылке; блокировка аккаунта закрывает все его сессии; себя заблокировать нельзя; фильтр «Репетиторы».
   Было в плане: В «Платформе»: аудитории, записи и материалы любого пространства, вход в аудиторию, блокировка и разблокировка пространств и аккаунтов (блокировка — на сервере, при входе и в каждом запросе).
5. **Э15.5 Библиотека «Матиса».** Отдельная область владения «платформа» вместо служебной школы; управление — супер-админ; доступ школ и репетиторов — по тарифу; копия в библиотеку школы без изменения оригинала.
6. **Э15.6 Лимиты тарифов.** Число аудиторий, методисты, доступ к библиотеке, записи — по каталогу тарифов (цифры даёт владелец).

## Открытый вопрос

§5.1 спецификации: репетитор «создаёт и использует личные аудитории» в пределах тарифа. Ранее (25.10.2026) владелец сказал, что репетитор аудитории **не создаёт** — они выдаются тарифом при создании профиля. Нужно выбрать одно до Э15.6.
