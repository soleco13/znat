# TURN поверх TLS на порту 443

Статус: подготовлено, **не включено**. Нужен внешний инфраструктурный шаг.

## Зачем

Сейчас медиа идёт так: UDP напрямую в LiveKit (50000–60000) → TCP 7881 → TURN UDP 3478 → TURN/TLS 5349. В сетях, где наружу открыт только 443 (школьные фильтры, гостевой Wi-Fi, часть корпоративных сетей), все четыре пути закрыты и звук с видео не подключаются, хотя сайт открывается. Контур.Толк в таких сетях работает через `turns:…:443?transport=tcp` на отдельных адресах.

## Почему нельзя просто поставить 443

У сервера один IPv4 (`213.21.241.28`), его 443/TCP занимает Caddy (сайт и сигнализация LiveKit). coturn на тот же адрес и порт не встанет.

## Варианты

| Вариант | Что нужно | Плюсы | Минусы |
|---|---|---|---|
| **A. Второй IPv4 под TURN** (рекомендую) | дополнительный адрес у хостинга, DNS-имя для TURN, сертификат на это имя | coturn слушает свой `IP2:443`, Caddy не трогаем; TLS-сертификат обычный | платный адрес у части хостингов |
| B. Мультиплексор на 443 | перед Caddy и coturn — L4-прокси с разбором SNI (`nginx stream` + `ssl_preread`), отдельное имя для TURN | один адрес | меняется вход всего сайта, лишняя точка отказа, Caddy теряет реальный IP клиента без PROXY protocol |
| C. Отдельный маленький сервер под TURN | VPS с публичным IP | заодно второй TURN-узел (резерв) | ещё одна машина |

## Шаги для варианта A

1. Получить у хостинга второй IPv4 `IP2`, поднять его на `ens3`.
2. DNS: `turn.<домен>` → `IP2`. Сертификат на это имя положить в `turn-certs/` (как сейчас `turn_cert.pem`/`turn_key.pem`).
3. coturn — текущий сервис не трогать (3478 и 5349 остаются, кто ими пользуется, не ломается). Добавить второй сервис `coturn-443` (тот же образ, `network_mode: host`) с `--listening-ip=IP2 --relay-ip=213.21.241.28 --tls-listening-port=443 --listening-port=3479` и теми же `--static-auth-secret`, `--realm`, `--denied-peer-ip`, `--allowed-peer-ip`, `--no-tcp-relay`, `--user-quota`, `--max-bps`, `--min-port/--max-port` из другого диапазона (ограничения G-10 сохранить). Основной coturn ограничить `--listening-ip=213.21.241.28`, чтобы он не занял `IP2`.
4. LiveKit `rtc.turn_servers` — добавить третий сервер (порядок важен: браузер пробует все, но TLS/443 — последний рубеж):
   ```yaml
   - host: turn.<домен>
     port: 443
     protocol: tls
     secret: ${TURN_SHARED_SECRET}
   ```
5. ufw: `ufw allow in on ens3 to IP2 port 443 proto tcp` — только на `IP2`, остальные правила не трогать.
6. Проверка: браузер в сети, где закрыто всё, кроме 443 (на стенде — `iptables -A OUTPUT -p udp -j DROP; iptables -A OUTPUT -p tcp ! --dport 443 -j DROP` в netns браузера), урок должен подключиться, в `chrome://webrtc-internals` выбранная пара — `relay` с `relayProtocol=tls`.

## Что не меняется

Учётные данные TURN по-прежнему выдаёт LiveKit по общему секрету (`use-auth-secret`), срок действия — как сейчас. Relay разрешён только к собственному адресу (`--allowed-peer-ip`), TCP-relay выключен.
