## 0. Суть изменения

**Было** (действующий ТЗ): у всех четырёх ролей — аккаунты с паролем. Ученик
логинится, состоит в группе, ответы на задания привязаны к его `user_id`,
учитель проверяет по фамилиям. Урок — сущность с расписанием и статусом
`scheduled → live → ended`.

**Стало** (решения пользователя 2026-09-06):
- Аккаунты и личный кабинет — только у **admin / methodist / teacher**.
- **Ученик аккаунта не имеет.** Открывает прямую ссылку на урок, вводит
  **произвольное имя** — без логина, пароля и без списка класса. Приложение
  ученика максимально простое.
- **Урок создаёт только admin.** Термин остаётся «урок». Урок — постоянный,
  без расписания и без статус-машины. У него есть имя, учитель, ссылка,
  настройки и журнал посещений.
- **Личность ученика на уроке = имя, которое он ввёл при входе** (+ стабильный
  гостевой id в куке-сессии, чтобы переподключение не теряло ответы).
- **Интерактивные задания на уроке — остаются.** Прогресс и ответы учитель
  видит по этим введённым именам. Живёт в пределах одного урока, между
  уроками не переносится, ученического дашборда нет.
- **Домашние задания = список материалов**, назначенных уроку. Учитель сам
  выбирает нужный. Сдачи ответов из дома и проверки домашки — нет.
- **UI урока переработать** под вид видеовстречи (§6): стейдж с плитками,
  нижняя панель управления, левый выдвижной блок инструментов, чат и
  участники — отдельными кнопками. **Из референса (KTalk) берём только
  структуру и раскладку, весь стиль — своя дизайн-система + shadcn.**
- **Группы/классы (`groups`, `group_members`) убираются** — они были нужны
  только для гейта «ученик состоит в группе» и для домашки по группе.
  Теперь ни того, ни другого нет.

## 1. Ревизия действующего ТЗ

После согласования правки вносятся в `docs/ТЗ.md` отдельным коммитом.

### 1.1 §1.1 / §1.2 — Продуктовые границы

| Пункт | Было | Стало |
|---|---|---|
| Роли | «администратор, методист, учитель, ученик. Всё.» | Те же, но **ученик — не учётная запись**. Ученик = участник урока с введённым именем, существует только в пределах сессии урока |
| §1.2 «не делаем» | «Личные кабинеты ученика/родителя с успеваемостью» | Дополнить: **у ученика нет ЛК и аккаунта вообще**; вход в урок только по ссылке; нет сдачи/проверки домашних заданий; нет классов/групп учеников |
| Урок | подразумевается расписание (`startsAt`, `durationMin`, `status`) | **Постоянный**, без расписания и статуса. Опциональное «плановое время» — только метка для сортировки, ничего не гейтит |

### 1.2 §4.2 — Роли и права

- «Вход в урок / Ученик ✅² (только если приглашён)» → **ученик входит по
  ссылке урока, вводит любое имя.**
- «Создание урока / ✅ Админ ✅ Учитель» → **только Админ.**
- Убрать «Видеть ответы других» (у учеников нет персистентной личности —
  ответы соседа и так не видны).
- «Запустить задание / Учитель ✅» — остаётся.
- «Скачать запись / Админ ✅ Учитель ✅» — остаётся.

### 1.3 §3.6 / §7 — Движок интерактивных заданий

**Остаётся.** Работает как сейчас, но личность отвечающего:

- было: `responses.user_id → users.id`;
- стало: `responses.participant_id → lesson_participants.id` (строка
  посещения с введённым именем и гостевым id).

Что убирается:
- **режим `homework`** у заданий (задание «на дом» со сдачей ответов) —
  вместо него «домашка = список материалов», см. ниже. Остаётся только
  `mode: 'live'` (задание на уроке).
- очередь ручной проверки **остаётся** — учитель проверяет открытые ответы
  по введённым именам в рамках этого урока. `grading.graded_by → users.id`
  (проверяет только персонал).
- аналитика по вопросу («17 из 24 выбрали B») — остаётся.

**Домашка = список материалов.** Уроку назначается набор материалов из
библиотеки; ученик по ссылке видит их и проходит сам, без сохранения
ответов. Отдельная сущность `lesson_materials`.

### 1.4 §8.1 — API

```
# урок (термин и таблица lessons сохраняются)
POST   /lessons                 → только admin;  { title, teacherId, settings }
GET    /lessons                 → admin: все; teacher: свои
GET    /lessons/:id
PATCH  /lessons/:id             → имя, настройки; только admin
POST   /lessons/:id/link/rotate → перевыпуск ссылки; только admin
GET    /lessons/:id/attendance  → журнал посещений (было /summary)
POST   /lessons/:id/start       → убрать (нет статуса)
POST   /lessons/:id/end         → убрать (внутренняя авто-очистка пустой комнаты остаётся)

# гостевой вход (новое)
GET    /j/:token                → { lessonTitle, settings }        публично, rate-limited
POST   /j/:token/enter          → { name } → гостевая сессия (httpOnly cookie)

# домашка = список материалов (новое)
GET    /lessons/:id/materials
POST   /lessons/:id/materials         { materialId }   только staff
DELETE /lessons/:id/materials/:mid

# задания на уроке — остаются, гость вызывает в пределах своего урока
GET    /activities/:id/my            материал без ключей — как сейчас
POST   /activities/:id/responses     { questionId, response }
POST   /activities/:id/submit        → { score, maxScore, feedback[] }
GET    /activities/:id/progress      учителю: прогресс по введённым именам
GET    /activities/:id/analytics
GET    /grading/queue                учителю: открытые ответы этого урока
POST   /grading/:responseId

# убрать
POST   /lessons/:id/activities  с mode:'homework'   → только 'live'
CSV-импорт учеников, /groups/*, /groups/:id/members → удалить целиком

# пользователи — только персонал
GET/POST/PATCH /users           роль ∈ {admin, methodist, teacher}
```

### 1.5 §10.11 — Аккаунты

- «Аккаунты заводит администратор… CSV-импортом класса» → **только персонал**.
  Учеников в `users` нет, CSV-импорт учеников удаляется.
- «Пароль ученик получает офлайн» → **у ученика нет пароля.** Ссылку на урок
  учитель раздаёт как угодно (мессенджер, дневник) — это не наш сервис.

### 1.6 §11 — Безопасность

Новый раздел «Гостевой доступ»:

| Аспект | Решение |
|---|---|
| Ссылка урока | `/j/:token`; `token` — 32+ байта случайности, на строке урока, перевыпуск admin (старый мгновенно недействителен) |
| Гостевая сессия | JWT `{ typ:"guest", lessonId, guestId, name }`, TTL ~6 ч, httpOnly+Secure+SameSite=Lax cookie; **не refresh** — истёк → перезаход по ссылке |
| Переподключение | пока кука жива — тот же `guestId`, ответы на задания сохраняются (ключ `responses.participant_id`) |
| Область гостя | только эндпоинты его одного урока: presence, чат, canvas (Yjs), назначенные материалы, задания урока. Ничего из `/users`, `/lessons` (список), `/materials` (библиотека) |
| LiveKit-токен гостю | `canSubscribe: true` всегда; `canPublish` — по настройкам урока + живым грантам учителя. Расширить `buildPublishGrant` — убрать завязку на `Role`, принимать `staff | guest + гранты` |
| Yjs-токен гостю | `canvas/hocuspocus.ts#onAuthenticate` принимает гостевой JWT; `readOnly = !canDraw` по гранту |
| Rate limit | `GET /j/:token`, `POST /j/:token/enter` — 20/мин на IP |
| 152-ФЗ | ПДн стало **меньше**: у учеников нет email и паролей. Введённое имя — ПДн, хранится в журнале посещений. Согласие на запись — баннер есть (Э10.3) |
| Мусорные имена | вход по произвольному имени — учитель может выгнать/замьютить участника (модераторские действия уже есть в `rooms/service.ts`) |

`media/service.ts`, `canvas/hocuspocus.ts`, `rooms/service.ts` — из списка
CLAUDE.md «не делегировать вслепую». Э12.5 — отдельный аккуратный под-этап
с тестами на реальном JWT и прогоном `/security-review`.

## 4. Риски и ограничения

1. **Проверить вживую в этой среде нельзя.** Без Docker LiveKit/Hocuspocus
   в полном сцепе не поднимаются (Postgres/Redis — есть, см.
   [[project_video_platform_env_gaps]]). Я собираю, проверяю типы, снимаю
   скриншоты несцепленной оболочки. Поведение урока (видео, доска-коллаб,
   демонстрация, гостевой токен end-to-end) проверяет пользователь у себя.
2. **Объём.** ~9 под-этапов, сопоставимо с Э1+Э8. Э11 в ТЗ — буфер; этот
   этап больше буфера. Реалистично — недели.
3. **Откат MVP-фич.** Убираем группы, CSV-импорт учеников, домашнюю сдачу
   заданий, статус-машину урока. Осознанное решение — фиксируем в ревизии ТЗ.
4. **Токены и права** (`media/service.ts`, `canvas/hocuspocus.ts`,
   `rooms/service.ts`) — «не делегировать вслепую». Э12.4 — отдельно, с
   security-review.
5. **152-ФЗ / §10.15** — не меняется; введённое имя в журнале посещений —
   ПДн, отразить в ревизии.

## 6. Новый UI урока — референс

Референс — клиент «Толк» (KTalk). Изучена живая комната пользователя
(`shkola10.ktalk.ru/oauja69oobi7`, гостевой вход) + скриншоты 2026-09-06.

**Из KTalk берём ТОЛЬКО:** какие панели есть, где они расположены, какой
контрол в какой группе, порядок кнопок, логику «панель поверх стейджа /
контент на стейдже». **Ничего из его визуала не копируем**: ни цвета, ни
тёмную тему, ни формы, ни иконки, ни отступы.

### Принцип оформления (действует на весь фронт Э12)

1. **shadcn — первым выбором.** Любой элемент интерфейса сначала ищем в
   реестре shadcn через **shadcn MCP** (`search_items` / `view_items` /
   `get_item_examples`) и ставим оттуда. Свою разметку пишем только там, где
   в реестре аналога нет (живое видео, дорожка сигнала, холст).
2. Готовый компонент **приводим к токенам ДС Shkola** (`src/index.css`,
   светлая тема) — как уже сделано с `button`/`toggle`/`aspect-ratio` на Э11.
   Меняем цвета/радиусы/тени под токены, структуру и поведение не трогаем.
3. Кандидаты из реестра под этот этап: `sidebar`, `sheet`, `resizable`,
   `scroll-area`, `dropdown-menu`, `dialog`, `tabs`, `tooltip`, `avatar`,
   `badge`, `button-group`, `toggle-group`, `empty`, `item`, `table`,
   `pagination`, `field`, `sonner`. Новые Radix-зависимости от них —
   согласованы (пользователь: «shadcn элементы приоритет»).
4. Цель — **качественный и красивый фронт**, а не минимально рабочий.

**Наблюдённая структура DOM (KTalk):**
- гостевой вход: экран «Представьтесь» (поле имени + «Запомнить имя» +
  «Продолжить» / «Войти как сотрудник организации») → экран устройств
  (камера / микрофон / динамики, «Присоединиться») → комната;
- в комнате guest = не-модератор: «Групповая сессия», «Таймер»,
  «Презентации», запись — **задизейблены** «только модератор». У нас
  модератор = teacher/admin, guest = ученик;
- плитка участника: аватар-круг с инициалами, чип имени слева снизу +
  иконка «микрофон выключен», кнопка «Меню действий» на плитке.

### 6.1 Верхняя строка
- слева: значок-бейдж с названием урока;
- справа: копировать ссылку · настройки · «…» (доп. меню).

### 6.2 Стейдж (центр)
- по умолчанию — плитки участников (учитель + до 9 видимых учеников, §5.2);
- один в комнате → крупная плитка + карточка «Вы пока один. Отправьте
  ссылку ученикам · [Копировать ссылку]»;
- доска / демонстрация / презентация / открытый материал → контент на весь
  стейдж, плитки сжимаются в ленту;
- один вид контента одновременно; переключает учитель, у всех синхронно.

### 6.3 Нижняя панель управления (всегда видна)
- **слева** (3 иконки): инструменты · участники (+счётчик) · чат;
- **центр**: рука (ученик) · демонстрация экрана · микрофон (+▾ выбор
  устройства) · камера (+▾) · запись · **выйти** (красная);
- **справа**: раскладка (сетка/спикер) · помощь.

### 6.4 Левая выдвижная панель — один блок, три режима
Слайдится поверх стейджа (~320–360px), переключается кнопками из §6.3:
- **Инструменты** — вертикальный список: доска вкл/выкл, презентации
  (`DeckPanel`), открыть материал классу (`LessonActivityPanel`), запись
  (`RecordingPanel`), режим урока, «разрешить рисовать всем», «заглушить
  всех», таймер/голосования (если оставим);
- **Участники** — «Участники / Модераторы», строка = аватар + имя + статус
  микрофона + значок роли + «…» (учителю: права, заглушить, закрепить, выгнать);
- **Чат** — лента, ряд быстрых эмодзи-реакций, поле ввода.

### 6.5 Доска (Excalidraw) — чистка
- убрать гамбургер-меню и его пункты (Open / Export / Reset / Help);
- убрать блок «Excalidraw links» (соцсети/GitHub);
- убрать кнопку «?» (help) справа внизу и подсказку-hint;
- `langCode="ru-RU"`;
- оставить только панель инструментов рисования;
- зум-контрол и наши кнопки страниц/undo — под ДС, на `shadcn`.
